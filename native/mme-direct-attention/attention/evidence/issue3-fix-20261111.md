# GitHub issue #3 fixes (2026-11-11)

Issue: https://github.com/JChen-318/gaudi2-single-card-vllm/issues/3 (reported against commit 6da6fb1).

## Problem 1: MAXFREE returns finite zeros; direct path falls back to it

Cause: `vllm_gaudi/omni/attention.py::max_free_attention` replaces the row maximum by the Cauchy-Schwarz
bound b = |q| * max|k| * scale. When a row's real maximum is far below b (anti-parallel or orthogonal
large-norm q/k), exp(s - b) underflows for the whole row and `row_sum.clamp(min=1e-30)` yields 0, a finite
wrong result. The production path had no runtime check (only the offline layer skip list 45/48/49). The
direct path's gates rejected such heads correctly but handed them to this same function.

Fix:
- `exact_attention(query, key, value, scale)` (vllm-gaudi): row-max softmax via FusedSDPA; an unaligned key
  length runs as aligned head + tail merged exactly (existing `kv_split_point` / `merge_kv_split`).
  With fewer heads than `PT_HPU_SDPA_HEAD_FACTOR` it duplicates heads: `sdpa_recomp_fwd` fails to compile
  for one head at head factor 2 (`issue3-headfactor.log`: factor 2 heads 1 fail at 37632 and 118 keys;
  heads 2 and 3 compile; factor 1 compiles for all).
- `max_free_attention` guard (default on, `VLLM_GAUDI_OMNI_SDPA_MAXFREE_GUARD=0` disables): the compiled
  chunk also returns each head's smallest row-sum margin, the padding-corrected row sum over
  max(1e-24, 1e-3 * padding term), so cancellation against the zero-padding term is caught too. One host read
  per call; heads below 1 are recomputed with `exact_attention` in one call per batch.
- Direct path: gate-rejected heads use `exact_attention` (or a local copy of it), never max-free.

## Problem 2: direct path only accepted L = 37750

Cause: H3 sequence length = 37296 video + 414 audio + text tokens. `VALID = 37750` (a 40-token prompt)
was checked at entry and compiled into the TPC programs (last key quarter's exp column count / exact-zero
padding bound, normalize length). A 50-token prompt (L = 37760) fell back for every call.

Fix:
- Only the TPC exp/normalize programs depend on the valid length. `quad_build_tpc` builds them,
  `context_quad_set_valid(valid)` rebuilds both slots' programs and `reupload_ecb` rewrites the existing
  device code in place (identical layout required, readback verified, no new pool memory). MME programs and
  the 56 head banks are untouched.
- Python: any 3 * FIRST < L <= KEYS runs direct; on a length change `set_valid`, then Q/V rows and K columns
  in [L, previous L) are zeroed (stale values must not reach PV as 0 * NaN). Gates use the actual L.
- Key-capacity bucket `H3DIRECT_KEYS`: 37760 (text <= 50 tokens, default, bit-identical to before) or
  38272 (text <= 562 tokens; first quarter 9600 = 5 x 1920, the G15 exp kernel's group; new compiler captures
  g-m512n9600k128 / g-m512n128k9600; native layout cap raised to 38272, SRAM end still checked).
